# API client reference

## Discovering operations

`$client->document()->operations()` returns every `Operation`, keyed by SDK ID. Each operation exposes `id`, `method`, `path`, `tags`, `definition` and `parameters()`.

Operations with an explicit `operationId` keep it. Otherwise, the ID is generated from the lower-case HTTP method and each alphanumeric route segment after `/open-api/v1`. Parameters become `By` followed by their PascalCase name; `/open-api/v1/` is `getRoot`.

Examples: `getVariants`, `getVariantsByVariantId`, `patchVariantsByVariantIdSellerStock`, `postAuthToken`, `postWebhookSubscription`. IDs are case-sensitive; the exact method/path interface is useful when upgrading specifications. Duplicate IDs stop loading rather than silently overwriting an API.

`composer api:list` emits JSON entries with tags, path, method, parameters, requestBody, responses and description. `--markdown` emits an operation table. Full payload descriptions and examples remain in the YAML.

## Client

```php
$client = new Client(new Configuration(
    accessToken: $token,
    baseUri: 'https://seller.digikala.com',
    timeout: 30.0,
    connectTimeout: 10.0,
));
```

`withAccessToken()` returns another client sharing the document/transport without changing the original client's configuration. Pass `http:` a Guzzle `ClientInterface` for dependency injection/testing; transport defaults such as TLS verification are still supplied per request.

`request(method, pathTemplate, options)` only accepts routes/methods present in the document. It cannot be used to fetch arbitrary external URLs. Configured origins must be HTTPS and have no path, credentials, query or fragment. Do not accept an origin or custom document path from an untrusted request. The SDK has no separate request-rate scheduler.

## RequestOptions

- `path`: named path values, each a non-empty string or integer; `.` and `..` are rejected.
- `query`: flat bracketed keys or nested arrays; RFC 3986 encoding and PHP-style array expansion.
- `body`: JSON/form/raw body, or `null` when omitted. For an object schema, an empty array is sent as `{}`.
- `multipart`: Guzzle multipart parts (`name`, `contents`, optional `filename`/`headers`). Use local streams and close resources after the call.
- `headers`: additional documented/custom headers. The SDK owns Host, Authorization, Content-Type and Content-Length. Header values cannot contain line breaks.
- `contentType`: explicitly selects a media type allowed by the requestBody. JSON or multipart is otherwise selected automatically.

```php
$result = $client->call('postProductCreationImagesUpload', new RequestOptions(
    multipart: [['name' => 'file', 'contents' => $stream, 'filename' => 'product.jpg']],
));
```

See `examples/upload.php` for safe resource handling. A multipart boundary is generated by Guzzle, overriding the document's blanket JSON header where appropriate. No file is opened from a URL by the SDK.

## Validation and source limitations

The bundled document includes nonstandard schema types (including `option`, `mixed` and combined type strings), `required: {}` entries, string-valued required flags, and a mapping-form tags section. The SDK loads it as YAML rather than pretending it passes a strict OpenAPI validator.

The input validator checks declared required parameters/body fields, standard scalar types, declared enums and array items. Document loading resolves local references for operations, parameters and requestBody mappings, but the input validator does not recursively resolve nested schema references. Unknown/nonstandard types are not guessed. Complete JSON Schema validation, format/size constraints and undocumented business rules are not implemented. Error values are not included in validation messages. Nested query input uses exact documented names.

Body examples in the upstream document can contradict the schema (for example an object instead of an array, or a brand name where an integer is declared). Do not copy every upstream example blindly. The fake contract input builder is test-only; those inputs must not be used for live mutations.

## ApiResponse

- `status(): int` or `statusCode(): int`: HTTP status.
- `json(): array`: decode a top-level JSON object or array; malformed/scalar JSON throws `UnexpectedValueException`.
- `data(): mixed`: obtain the envelope's `data` unchanged, or `null` when absent.
- `httpResponse(): ResponseInterface`: the original headers, binary content and body stream.
- `body(): string` and `header(string): string`: explicitly access raw content and individual headers.

```php
$result = $client->request('GET', '/open-api/v1/inventories/{product_variant_id}/export',
    new RequestOptions(path: ['product_variant_id' => $productVariantId]),
);
$rawResponse = $result->httpResponse();
```

The document describes this export as JSON containing a binary field. Inspect the actual response and do not assume a base64 encoding. Streaming to a file, maximum download size and file permissions belong to the application.

## Failure model

An HTTP failure (anything outside 2xx) or JSON `status: error` throws `ApiException`. `status()`, `errors()`, `response()` and `retryAfter()` are available. `Retry-After` is a string because it can be an integer delay or HTTP date. Error messages are intentionally generic. Explicitly accessed responses/errors may contain personal data; protect logs.

Network/TLS/timeout errors throw `TransportException`. Malformed client options, unknown IDs/routes and missing input throw `InvalidArgumentException`; malformed documents throw `RuntimeException`. Expired tokens are not refreshed automatically, and no call is automatically retried.

## Pagination

`$client->pages($operationId, $options, $maxPages)` lazily yields `ApiResponse` objects for documented GET operations with a `page` parameter. It increments `page` and finishes at `data.pager.total_pages`. Missing/invalid pagination metadata or reaching `maxPages` before completion throws `RuntimeException`, rather than silently presenting a partial result as complete. Start with a positive integer `page`. Pages are not flattened, so response metadata is preserved.
